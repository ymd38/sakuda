# Harness setup checklist

Generated by dev-skills setup. CI is strict by design — these are the
manual steps that turn it green and make the gates actually gate.

- [ ] Commit `.claude/`, `CLAUDE.md`, `.github/`, `.gitleaks.toml`, `.semgrepignore` and push `main`
- [ ] If re-running setup produced `*.new` files: diff, merge, delete them
- [ ] Node: add `lint / typecheck / test` scripts to `package.json` (CI preflight fails without them)
- [ ] Node: commit `pnpm-lock.yaml` (frozen-lockfile install requires it)
- [ ] Write the first test with the first code PR — zero tests fail CI by design
- [ ] After the first push: `setup.sh --protect` (requires repo ADMIN) so checks become required and actually block merges
- [ ] Review trivy findings; once triaged, delete `continue-on-error: true` in `security-scan.yml` (maturity Stage 1)
- [ ] Restart Claude Code so the hooks load
- [ ] Adjust CLAUDE.md commands if the defaults don't match your project

Delete this file when everything is checked.

- [ ] PR Agent: add the repository secret `OPENAI_KEY` (Settings → Secrets and variables → Actions) — until set, the `PR Agent` workflow fails on every PR (advisory only, never a required check)
- [ ] PR Agent: review `.pr_agent.toml` — `auto_describe` rewrites the PR body on open; pushes re-run only `/review`
